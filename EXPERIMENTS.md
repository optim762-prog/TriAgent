# TriAgent — Experiments Overview

## Setup

**Main dataset**: `datasets/instances.jsonl` — 100 instances across 5 agronomic processes (20 each). Weather data is **embedded** in descriptions.
**Main ground truth**: `datasets/ground_truth.jsonl` — keyword + range matching, no exact match.

**Tool-forcing dataset**: `datasets/tool_forcing_instances_n100.jsonl` — 100 instances (20 per process), same processes but weather is **absent** from descriptions; explicit phrase forces `get_weather` call.
**Tool-forcing ground truth**: `datasets/ground_truth_toolforcing_n100.jsonl` — `required_tool_calls: ["get_weather"]`, `gateway_decisions: {}` (not evaluated), `should_escalate: false`.
Generated by `experiments/generate_toolforcing.py`.

**Evaluation** (Docker):
```bash
docker compose -f infra/docker-compose.yml run --rm --no-deps \
  --entrypoint python triagent-runner \
  experiments/evaluate.py --results <results_dir> --gt <gt_file>
```
- For main runs: `--gt datasets/ground_truth.jsonl` (default)
- For tool-forcing: `--gt datasets/ground_truth_toolforcing_n100.jsonl`
- Output: `results/aggregated/`

## System versions

Two configurations, differing in two improvements introduced on 2026-06-12:

| Version | FAISS knowledge base | Weather pre-fetch | Tool calling |
|---|---|---|---|
| **v1 — old system** (Jun 9–11) | Seed rules only (9 hand-written) | Pre-fetched before LangGraph loop | Never triggered (`tools_ok = 0.0`) |
| **v2 — new system** (Jun 12+) | CIMMYT PDF rules (real document) | Suppressed (`--skip-prefetch`) | Triggered via `requires_tool: true` |

Improvement A = CIMMYT PDF in FAISS. Improvement B = working tool execution.

---

## Ablation modes

| Mode | Knowledge Agent | Execution Agent | Tests |
|---|---|---|---|
| `full` | FAISS retrieval → rule | Live tool calls | A + B combined |
| `no_knowledge` | Bypass FAISS; pass raw description | Live tool calls | B only (with `--skip-prefetch`) |
| `no_execution` | FAISS retrieval → rule | Returns `TOOL_DISABLED_FOR_ABLATION` | A only |

Factor isolation design (new system):

```
no_execution            → CIMMYT PDF effect only       (A, no tool calling)
no_knowledge + skip     → Tool calling effect only      (B, no FAISS)
full + skip             → A + B combined                (full new system)
```

Baseline for each comparison: the corresponding v1 run (same backbone, same ablation mode).

**v1 prerequisite**: FAISS store must be pre-seeded before each batch:
```bash
docker compose -f infra/docker-compose.yml run --rm triagent-runner \
  seed --rules /app/datasets/seed_rules.jsonl
```

## Infrastructure

- **Local** (24 GB VRAM):
  `infra/docker-compose.yml` — llama.cpp server + triagent-runner
- **Local models**:
  - `gemma4-local`: `unsloth/gemma-4-26B-A4B-it-GGUF` Q4_K_XL (~18 GB)
  - `qwen-local`: `unsloth/Qwen3.6-27B-MTP-GGUF` UD-Q4_K_XL (~16 GB)
  - Swap: stop server, change env, restart, wait for healthcheck
- **Cloud**: DeepSeek (`deepseek-chat`) — `--no-deps`, no llama.cpp needed

Batch command pattern (v2 new system):

```bash
docker compose -f infra/docker-compose.yml run --rm triagent-runner \
  batch \
  --input  /app/datasets/instances.jsonl \
  --output /app/results/v2_new_system/<backbone>__<ablation>__n100/results.jsonl \
  --backbone <backbone> --provider <provider> --ablation <mode> [--skip-prefetch]
```

Multi-job runners: `infra/run_main_skipprefetch.sh` (Gemma4 + DeepSeek full+skip),
`infra/run_qwen_newsystem.sh` (Qwen all ablations, needs server swap first).

## Key findings

**F1 — FAISS pre-seeding is necessary (v1).**
Without seed rules, cold-start causes P3 `full` escalation 50%. With seeding:
Qwen full 0.350 → 0.417, gateway_ok 0.270 → 0.470.

**F2 — full > no_knowledge confirmed in both versions.**
v1: Gemma4 0.443 > 0.410; Qwen 0.417 > 0.377.
v2: Gemma4 0.488 > 0.405; Qwen 0.485 > 0.423; DeepSeek 0.433 > 0.377.
KnowledgeAgent adds consistent value across all models and both system versions.

**F3 — full > no_execution in v2 (hypothesis confirmed); reversed in v1.**
v1: no_execution > full (Gemma4 0.500 > 0.443) — tools never fired, execution node only added stalling risk.
v2: full+skip ≥ no_execution for Gemma4 (0.488 > 0.485) and Qwen (0.485 > 0.483).
DeepSeek still shows no_execution > full+skip (0.443 > 0.433) — small gap, may be noise.
Conclusion: when tools actually fire, the full 3-agent system is best or co-best.

**F4 — v2 system improves over v1 across all models.**
Gemma4 full: +0.045 (0.443 → 0.488). Qwen full: +0.068 (0.417 → 0.485). DeepSeek full: +0.053 (0.380 → 0.433).
Both improvements (CIMMYT PDF rules + live tool execution) contribute.

**F5 — Gemma4 ≈ Qwen in v2; both well ahead of DeepSeek.**
v2 full+skip: Gemma4 0.488, Qwen 0.485, DeepSeek 0.433.
v1 gap between local models was larger; CIMMYT PDF rules helped Qwen most (+0.068).

**F6 — DeepSeek underperforms local models on structured protocol reasoning.**
v1: 0.380, 37% escalation. v2: 0.433 — improved but still lowest.
Cloud inference speed ≠ structured reasoning capability.

**F7 — Tool calling confirmed on tool-forcing dataset (n=100, 2026-06-14).**
On 100 instances with weather absent from descriptions, all three models invoke `get_weather`
via `requires_tool: true`: Qwen 100/100, DeepSeek 100/100, Gemma4 99/100 (tools_ok 1.00/1.00/0.99).
Overall scores rise to 0.843/0.793/0.840 vs 0.485/0.433/0.488 on production dataset, primarily
because tools_ok flips from 0.0 to ~1.0 (1/6 of overall). This isolates the production
tools_ok=0.0 as a dataset artifact (embedded weather) rather than a system failure.
`dose_ok` remains low (0.15–0.26): models recommending "monitor" (agronomically correct when
live weather shows LOW risk) produce no specific L/ha value to match against GT range.

**F8 — Monolithic baseline confirms gateway as the structural differentiator (n=100, 2026-06-15).**
Single-shot monolithic LLM baseline evaluated on the same production dataset.
Monolithic achieves higher substance (0.52–0.63 vs 0.23–0.29) and diagnosis (1.0 vs 0.92–0.97)
due to a direct prompt that explicitly requests these fields without multi-step overhead.
DeepSeek monolithic overall (0.495) marginally exceeds TriAgent full (0.433) on this dataset.
However, gateway_ok = 0.000 for ALL monolithic runs — a structural zero, not a near-miss.
TriAgent Full achieves 0.400–0.510 gateway accuracy on the same dataset, directly validating
Theorem 1: collapsing K+R+E into a single inference step makes it constitutively impossible
to enforce process-level regulatory decision gateways regardless of backbone capability.
On the tool-forcing dataset, the gap widens further: tools_ok 1.0 (TriAgent) vs 0.0 (monolithic).
